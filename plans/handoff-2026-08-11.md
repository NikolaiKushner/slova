## Решения, которые не надо перерешивать

1. **Слово глобально у пользователя.** Одно слово в трёх наборах — одна запись,
   один прогресс. Идентичность — `normalizeKey(front)` из `lib/lexicon/key.ts`.
   Ту же функцию обязан использовать лексикон, иначе посев не попадёт в
   собственный индекс, и промах будет неотличим от незнакомого слова.
2. **Миграции добавочные, историю не переписываем.**
3. **LLM — `claude-haiku-4-5`, structured outputs, стриминг.** Проверено живым
   вызовом: схема принимается, поток реально идёт кусками.
   - **`effort` на Haiku 4.5 не существует** — параметр возвращает 400. Он есть
     только у Sonnet 5 / Opus, которые втрое-впятеро дороже. То есть «самая
     дешёвая модель» и «low» взаимоисключающи. `lib/llm/models.ts` держит карту
     возможностей, тест это фиксирует.
   - Prompt caching не использовать: минимальный кэшируемый префикс на Haiku 4.5
     — 4096 токенов, наш системный промпт ~250, кэш молча не создастся.
   - Batch API — вдвое дешевле, но до 24 часов. Только для посева, не для
     интерактива.
4. **Общая база — кэш, а не истина.** `seed` и `llm` глобальны сразу; перевод,
   напечатанный человеком, ложится кандидатом `isGlobal=false` и становится
   общим после второго независимого подтверждения (`confirmations >= 2`).
   Плохое поколение гасится bump'ом `version`, без удаления данных.
5. **Пустой перевод — не ответ, а промах.** Модель возвращает пустую строку,
   когда не может перевести (проверено: `was/were`). Записанный в базу, он
   считался бы попаданием вечно, и слово никогда не переспросили бы. Отбрасывается
   и при сборке датасета, и при загрузке.
6. **`UserWord.lexemeId` — без внешнего ключа**, намеренно: общая база физически
   отвязана от пользовательских данных.
7. **Лемматизация — вне рамок.** `monitor` и `monitored` пока разные записи.

## Окружение и грабли

- **База одна** — `neondb`, она же прод. `slova_dev` удалена 2026-08-11.
  Миграции авторить через `npx prisma migrate diff --from-config-datasource
  --to-schema ./prisma/schema.prisma --script` (только читает базу), применять
  деплоем. `migrate dev`, `migrate reset` и `db push` против прода не запускать —
  последние две запрещены правилом в `.claude/settings.local.json`.
- **`dotenvx` печатает баннер `◇ injected env …` в stdout.** При
  `prisma migrate diff --script > migration.sql` он попадает первой строкой в
  SQL, и `migrate deploy` падает на проде. После генерации миграции смотреть
  `head -1`.
- **В Prisma 7 у `migrate diff` другие флаги:** `--to-schema`, а не
  `--to-schema-datamodel`; `--from-migrations` требует shadow-базы.
- **`tsx` компилирует `.ts` в CJS** (в `package.json` нет `"type": "module"`),
  поэтому top-level await в скриптах — синтаксическая ошибка. Оборачивать в
  `async function main()`.
- **`grep` буферизует вывод, когда пишет не в терминал.** Прогресс долгого
  скрипта через `| grep -v …` не виден до конца работы.
- **Vercel CLI глобально не установлен**, работает `npx vercel`.
- **`npx vercel link` перезаписывает `.env.local`** — после него проверять
  `DATABASE_URL`.
- **Миграции ходят через `DATABASE_URL_UNPOOLED`** (`prisma.config.ts`), рантайм —
  через пулер.
- Попытка `DROP SCHEMA public` на проде **блокируется классификатором прав**.
- Git-идентичность задана **локально в репозитории** (`git config --local`).
- **`npm test` перед пушем в `main` обязателен.** Dev-сервер, e2e и браузеры в
  агентских сессиях не запускать.

## Цифры, замеренные живьём (2026-08-11)

Один запрос, 40 медицинских слов, `claude-haiku-4-5`:

| | |
|---|---|
| Полное время | 3971 мс |
| Первая заполненная строка | 1418 мс |
| Токены | 612 вход / 706 выход ≈ 17,7 выходных на слово |
| Цена | $0.0041 за 40 промахов |

Отсюда: посев 9822 слов — ~$0.93 обычным API, ~$0.46 батчем. Дневной лимит из
шага 4 (50 запросов) — потолок ~$0.20 на пользователя в сутки. Список, целиком
попавший в лексикон, стоит $0 — ради этого всё и делается.
