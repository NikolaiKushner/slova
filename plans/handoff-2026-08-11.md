## Решения, которые не надо перерешивать

1. **Слово глобально у пользователя.** Одно слово в трёх наборах — одна запись,
   один прогресс. Идентичность — `normalizeKey(front)` из `lib/lexicon/key.ts`.
   Ту же функцию обязан использовать лексикон: если общая база нормализует иначе,
   она промахнётся по словам, которые в ней есть, и промах будет неотличим от
   незнакомого слова.
2. **Миграции добавочные, историю не переписываем.** Соблазн «удалить init и
   написать чистый» стоит ручного сброса прод-схемы. Не надо.
3. **LLM — `claude-haiku-4-5`, structured outputs, стриминг.**
   - `output_config.effort` на Haiku 4.5 **возвращает 400** — параметра там нет.
     В `lib/llm/models.ts` должна быть карта возможностей, `effort` подставляется
     только для моделей, которые его принимают (Sonnet 5, Opus 5, Opus 4.5+).
   - Prompt caching не использовать: минимальный кэшируемый префикс на Haiku 4.5 —
     4096 токенов, наш системный промпт короче, кэш молча не создастся.
   - Batch API — только для разового посева, не для интерактивного перевода.
4. **Общая база — кэш, а не истина.** `seed` и `llm` глобальны сразу; перевод,
   напечатанный человеком, ложится кандидатом `isGlobal=false` и становится общим
   только после второго независимого подтверждения (`confirmations >= 2`).
   Плохое поколение гасится bump'ом `version`, без удаления данных.
5. **Посев — частотный топ ~10–20 тыс.** Органика на одном пользователе покрытия
   не даст. Атрибуция в футере владельца устраивает; помнить, что CC BY-SA
   наследуется производным набором, если базу когда-нибудь начнут отдавать наружу.
6. **`UserWord.lexemeId` — без внешнего ключа**, намеренно: общая база физически
   отвязана от пользовательских данных и может уехать в отдельный проект.
7. **Add words остаётся пунктом сайдбара.** На My words будет quick add (шаг 8),
   селектор набора — на странице добавления (шаг 10).
8. **Лемматизация — вне рамок.** `monitor` и `monitored` пока разные записи.

## Окружение и грабли

- **Vercel CLI глобально не установлен**, работает только `npx vercel`. Проект
  слинкован (`npx vercel link --yes` уже выполнен).
- **`npx vercel link` перезаписывает `.env.local`** — после него проверять, куда
  смотрит `DATABASE_URL`.
- **`.env.local` сейчас смотрит на базу `slova_dev`** — отдельную базу внутри того
  же проекта Neon. Прод-строки сохранены рядом строками вида
  `# prod (Vercel): DATABASE_URL=...`. **Открытый вопрос:** владелец предложил
  оставить одну базу и не морочиться до появления пользователей. Если так —
  снести `slova_dev` и вернуть `DATABASE_URL`/`DATABASE_URL_UNPOOLED` на `neondb`.
  Тогда миграции авторить через `npx prisma migrate diff --from-migrations
  ./prisma/migrations --to-schema-datamodel ./prisma/schema.prisma --script`
  (не трогает базу вообще), а применять деплоем. `migrate dev` и `migrate reset`
  против прода не запускать.
- **Миграции ходят через `DATABASE_URL_UNPOOLED`** (`prisma.config.ts`), рантайм —
  через пулер.
- `prisma migrate reset` требует переменной
  `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION` с точным текстом согласия
  пользователя.
- Попытка сделать `DROP SCHEMA public` на проде **блокируется классификатором
  прав** — обходить не пытаться, просить пользователя.
- Git-идентичность задана **локально в репозитории** (`git config --local`), потому
  что в глобальных конфигах её нет. `~/.gitconfig-dev` включал сам себя и ломал git
  во всём `~/dev`; владелец это починил, бэкап лежит как `~/.gitconfig-dev.bak-*`.
- **`npm test` перед пушем в `main` обязателен** (`CLAUDE.md`). Dev-сервер, e2e и
  браузеры в агентских сессиях не запускать.
